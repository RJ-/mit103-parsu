# Week 11 — Designing Display Outputs, Dashboards and Web Output

**Program outcomes:** `a.4` · `i.1`  
**Portfolio thread:** System Physical Design

## Learning outcomes

By the end of this week you should be able to:

- Design effective display outputs for users.
- Develop dashboards, widgets and user-centered visual outputs.
- Apply the principles of designing web and mobile outputs.
- Apply output design principles in creating modern digital interfaces.

## Instructional content

- Designing display outputs
- Dashboard, widgets and gadgets design
- Website output design (e-commerce and corporate systems)
- Introduction to Web 2.0 technologies
- Output design for mobile applications (smartphones and tablets)

## In class

- **Lecture-discussion (30 min).** Output design objectives applied to screens: purpose, audience, timing, medium.
- **Hands-on design activity (60 min).** Sketch a dashboard for your domain on paper first, then move to Penpot. Paper first is not optional — it prevents premature commitment to a tool's defaults.
- **Peer critique (30 min).** Rotate sketches; each reviewer names one thing the dashboard makes easy and one decision it makes harder.

## Lab and independent work

- Build the primary output screen for your system in **Penpot**, at medium fidelity.
- Run a WCAG 2.2 contrast and structure check; record failures and fixes.
- Produce a mobile variant of the same output and note what you dropped.

## Assessment

System Physical Design output — initial output/interface design, rubric-assessed (Laboratory/Performance, 40%).

## Check yourself

- What decision does your dashboard support? If you cannot name one, it is a report, not a dashboard.
- Which metric on your screen would a user act on today?
