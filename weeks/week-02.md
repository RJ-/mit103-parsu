# Week 02 — Systems, Roles and Development Methodologies

**Program outcomes:** `a.1` · `a.3` · `d.2`  
**Portfolio thread:** Problem domain selection

## Learning outcomes

By the end of this week you should be able to:

- Recall the basic types of computer-based systems a systems analyst must address.
- Explain how users working in context with new technologies change the dynamics of a system.
- Distinguish the roles a systems analyst plays across a project.
- Compare the fundamentals of three development methodologies: SDLC, the agile approach, and object-oriented systems analysis and design.

## Instructional content

- Systems, roles and development methodologies
- Basic types of computer-based systems
- Users and new technologies in system dynamics
- Roles of a systems analyst
- SDLC, Agile, and Object-Oriented Systems Analysis and Design

## In class

- **Lecture discussion (40 min).** Types of computer-based systems; the analyst as consultant, supporting expert and agent of change.
- **Interactive discussion — methodology matrix (45 min).** In pairs, complete a comparison across SDLC, Agile and OOSAD on: how requirements are treated, how change is absorbed, what documentation survives, and where each fails. Pairs post their matrix to the board; the class reconciles disagreements.
- **Concept sharing (20 min).** Each student states which methodology their own workplace actually uses, versus which one it claims to use.

## Lab and independent work

- **Git onboarding (45 min).** Clone your fork, create a branch, commit a file, open a pull request. See [CONTRIBUTING](../CONTRIBUTING.md) for the exact workflow.
- **PlantUML first diagram.** Write a five-line use case diagram as code, commit it, and confirm it renders in GitHub.
- Submit your problem domain statement as a pull request to `submissions/<your-surname>/domain.md`.

## Assessment

Recitation and individual presentation (Class Standing, 20%). Git workflow completion is a lab checkpoint.

## Check yourself

- The Agile Manifesto values working software over comprehensive documentation. In a government agency subject to COA audit, what does that trade-off cost you, and how would you mitigate it?
- Name a project type where OOSAD is a poor fit and justify the claim.
