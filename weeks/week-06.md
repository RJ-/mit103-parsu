# Week 06 — Agile Modeling and Prototyping

**Program outcomes:** `a.4` · `c.4`  
**Portfolio thread:** System Prototype

## Learning outcomes

By the end of this week you should be able to:

- Explain the roots of agile modeling in prototyping and distinguish the four main types of prototyping.
- Use prototyping for human information requirements gathering.
- Apply the concept of RAD in requirements gathering and interface design.
- Identify the core practices that differentiate agile modeling from other development methodologies.
- Explain the values critical to agile modeling.
- Improve efficiency for knowledge workers using either structured methods or agile modeling.

## In class

- **Lecture (30 min).** Four types of prototypes: patched-up, non-operational, first-of-a-series, selected features. RAD and its trade-offs.
- **Group dynamics — sprint zero (60 min).** Teams of 3–4 build a product backlog in Taiga from one team member's SRS, estimate, and commit to a one-week sprint.
- **Case study (30 min).** A prototype that was mistaken for a finished product. What governance would have prevented it?

## Lab and independent work

- Set up **Penpot** and build a low-fidelity clickable prototype covering your three highest-value user tasks.
- Set up **Taiga** and populate the backlog. Screenshot the board for your submission.
- Run one prototype walkthrough with a real or proxy user and record what changed as a result.

## Assessment

System Prototype, rubric-assessed (Laboratory/Performance, 40%). See [System Prototype](../deliverables/02-system-prototype.md).

## Check yourself

- Which of the four prototype types did you actually build? Be honest, then justify the fit.
- What did your walkthrough participant do that you did not anticipate?
