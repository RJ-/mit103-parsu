# Week 18 — Quality Assurance, Implementation, SOA and Cloud

**Program outcomes:** `a.5` · `g.3` · `i.3`  
**Portfolio thread:** Detailed System Proposal (Chapters 1–5) and Implementation Result

## Learning outcomes

By the end of this week you should be able to:

- Recognize the importance of users and analysts taking a total quality approach to improve the quality of software design and maintenance.
- Explain the importance of documentation, testing, maintenance and auditing.
- Explain how service-oriented architecture and cloud computing are changing the nature of information system design.

## Instructional content

- Quality assurance and implementation

## In class

- **Discussion (30 min).** Total quality approach; walkthroughs, audits and the six-sigma inheritance in software.
- **Interactive learning (40 min).** Map your system against all nine ISO/IEC 25010 characteristics and identify the two you have evidence for and the two you have neglected.
- **Panel defence (40 min).** Each student presents and defends their system to a panel — this rehearses PO9 i.3.

## Lab and independent work

- Assemble the **Detailed System Proposal** in Chapters 1–5 research format.
- Package the **Implementation Result** with evidence: test records, screenshots, deployment notes.
- Final repository hygiene: README, licence attribution, clean commit history.

## Assessment

Detailed System Proposal and Implementation Result (Laboratory/Performance, 40%) plus the **Final Examination** (Midterm/Final Exam, 30%). See [Final Proposal](../deliverables/07-final-proposal.md).

## Check yourself
