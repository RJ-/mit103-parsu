# Week 13 — Web, Intranet and Tablet Input Design

**Program outcomes:** `a.4` · `i.1`  
**Portfolio thread:** System Physical Design — submission

## Learning outcomes

By the end of this week you should be able to:

- Design useful input forms for people interacting on the Web.
- Design useful input pages for users of intranets, the Web, smartphones and tablets.
- Apply usability and accessibility principles in creating input interfaces across platforms.

## Instructional content

- Web-based input design
- Input pages for intranets and websites
- Input design for smartphones and tablets
- Usability and accessibility considerations in input design

## In class

- **Lecture-discussion (25 min).** Constraints that change across platforms: touch targets, virtual keyboards, connectivity, interruption.
- **Interface prototyping (60 min).** Take one desktop form to tablet and phone. What breaks first?
- **Peer critique (35 min).** Structured critique using the accessibility checklist.

## Lab and independent work

- Complete the responsive input set for your system: desktop, tablet, phone.
- Submit the full **System Physical Design** package as a pull request.

## Assessment

System Physical Design submission, rubric-assessed (Laboratory/Performance, 40%). See [Physical Design](../deliverables/05-physical-design.md).

## Check yourself

- On a phone, with one thumb, on a slow connection — can your user still finish the task?
- Which platform did you design for first, and how did that bias the others?
