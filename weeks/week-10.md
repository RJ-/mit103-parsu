# Week 10 — Process Specifications, Structured Decisions, and Introduction to Output Design

**Program outcomes:** `a.3` · `d.2` · `a.4` · `g.1`  
**Portfolio thread:** System Logical Design

> **Scheduling note.** The syllabus places *Introduction to Output Design* in a second block alongside Week 10's process specifications content. If your class schedule splits these across two sessions, teach process specifications first — output design depends on it.

## Learning outcomes

By the end of this week you should be able to:

- Explain the purpose of process specifications.
- Distinguish structured from semi-structured decisions.
- Use structured English, decision tables and decision trees to analyze, describe and document structured decisions.
- Choose an appropriate decision analysis method for a given process specification.
- State the objectives of effective output design.
- Relate output content to output methods within and outside the organizational context.
- Recognize how output bias affects users and decision-making.

## Instructional content

- Process specifications and structured decisions
- Introduction to output design; objectives of effective output design
- Types of outputs (internal vs external); output methods and media
- Output bias and its implications

## In class

- **Discussion (30 min).** When structured English beats a decision table, and when neither is adequate.
- **Brainstorming — decision table build (40 min).** Take a real policy (leave approval, discount eligibility, enrolment) and build the complete table. Count the rules; find the ones nobody in the room can answer.
- **Interactive learning — output bias (40 min).** Compare two presentations of the same dataset. Identify the design choices that steer the reader, then discuss the analyst's ethical obligation (PO8 h.1).

## Lab and independent work

- Write process specifications for every primitive process in your Level-1 DFD, using structured English, a decision table or a decision tree — and justify each choice.
- Render at least one specification as a PlantUML activity diagram committed as code.
- Short analysis activity: evaluate an existing output from your organisation against effective-output-design criteria (one page).

## Assessment

System Logical Design, rubric-assessed (40%); recitation and short analysis activity (Class Standing, 20%).

## Check yourself

- Your decision table has 2^n rule columns for n conditions. Did you enumerate all of them, or only the ones you had answers for?
- Name an output in your organisation whose format changes the decision it supports.
